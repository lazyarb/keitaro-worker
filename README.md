# LazyArb Keitaro Worker

Open-source, durable postback delivery for the LazyArb Keitaro integration.

A LazyArb custom redirect writes a small event to an atomic local file queue and immediately continues the click. This worker delivers queued events asynchronously, retries temporary failures, and preserves exhausted events for inspection.

## Runtime model

Keitaro 10 and 11 use the same static Go binary and restricted systemd service on the customer's server:

- binary: `/usr/local/libexec/lazyarb-keitaro-worker`;
- queue: `/var/lib/lazyarb-keitaro`;
- endpoint registry: `/etc/lazyarb-keitaro/endpoints.d`;
- log: `/var/log/lazyarb-keitaro/worker.log`.

Keitaro 11 runs its tracker in a container, so the installer adds one host queue bind mount to the tracker. The worker itself never runs in Docker. Keitaro 10 writes to the same host queue directly.

See [Architecture](docs/architecture.md) and [Security model](docs/security-model.md).

## Installation

Normal installations are generated by the LazyArb web application. The generated installer:

1. Downloads the pinned `install-runtime.sh` and verifies its SHA-256 digest.
2. Downloads the matching `amd64` or `arm64` binary and verifies its SHA-256 digest.
3. Writes the endpoint URL to the protected registry.
4. Installs the generated Keitaro redirect atomically.
5. Starts the systemd service and checks its heartbeat.

The first Keitaro 11 installation adds the queue mount and runs `kctl tune`. This restarts Keitaro tracker services and can interrupt campaign traffic for several seconds. Reinstalling with the existing mount does not tune the tracker again.

## Data locations

| Path | Contents | Access |
| --- | --- | --- |
| `/var/lib/lazyarb-keitaro/{tmp,pending,processing,retry,failed}` | Durable queue | Tracker and worker |
| `/var/lib/lazyarb-keitaro/state` | Lock and heartbeat | Worker |
| `/etc/lazyarb-keitaro/endpoints.d/*.url` | Postback endpoint URLs and tokens | Worker and root |
| `/var/log/lazyarb-keitaro/worker.log` | Delivery and retry JSON log | Worker and root |

Failed events can include ad and Keitaro sub IDs. Treat queue backups as customer data.

## Local development

```sh
make verify
make build
dist/keitaro-worker version
sh -n install-runtime.sh
scripts/test-install-runtime.sh
```

Run one queue batch without starting a daemon:

```sh
LAZYARB_QUEUE_ROOT=/tmp/lazyarb/queue \
LAZYARB_ENDPOINTS_ROOT=/tmp/lazyarb/config/endpoints.d \
LAZYARB_LOG_FILE=/tmp/lazyarb/log/worker.log \
go run ./cmd/keitaro-worker once
```

## Delivery guarantees

- Atomic queue publication on the local filesystem.
- Bounded concurrent delivery with pooled HTTP connections.
- Exponential retries for network errors, HTTP 408/425/429, and 5xx responses.
- Immediate dead-lettering for permanent 4xx responses.
- Recovery of interrupted processing and partially published queue files.
- At-least-once delivery: a crash after the receiver commits but before local acknowledgement can produce a duplicate request.

## Releases

Tags matching `v*` publish Linux `amd64` and `arm64` static binaries, SHA-256 checksums, and a keyless Cosign signature bundle for the checksum file. Releases are built on LazyArb self-hosted runners.

Code from external forks is not executed automatically on persistent runners. Maintainers review it before running CI from an organization branch.
