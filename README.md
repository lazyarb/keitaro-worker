# LazyArb Keitaro Worker

Open-source, durable postback delivery for the LazyArb Keitaro integration.

A LazyArb custom redirect persists a small event to a local atomic file queue and immediately continues the click redirect. This worker delivers queued events independently, retries temporary failures, and preserves exhausted events for inspection.

## Runtime model

The worker always runs on the customer's Keitaro server. GitHub and GHCR distribute source code and immutable release artifacts; they are not in the postback delivery path.

- **Keitaro 11:** a dedicated, non-root container runs beside the tracker container. It has no Docker socket and cannot access Keitaro application files or databases.
- **Keitaro 10:** a static Go binary runs as a restricted systemd service when a separate container is unavailable.
- **Storage:** the queue remains on the Keitaro host under `/var/lib/lazyarb-keitaro` and survives worker or tracker replacement.
- **Credentials:** endpoint URLs are stored in root-managed files under `/etc/lazyarb-keitaro/endpoints.d`; new queue events contain only a non-secret endpoint ID.

See [Architecture](docs/architecture.md) and [Security model](docs/security-model.md).

## Installation

Normal installations are generated by the LazyArb web application. The generated wrapper:

1. Downloads this repository's pinned `install-runtime.sh` and verifies its SHA-256 digest.
2. Installs the pinned container image or static binary.
3. Writes the endpoint URL to the protected endpoint registry.
4. Installs the generated Keitaro redirect atomically.
5. Validates the queue mount and worker health.

The first Keitaro 11 installation adds a tracker bind mount and runs `kctl tune`. That restarts Keitaro tracker services and can interrupt campaign traffic for several seconds. Reinstalling or upgrading an existing mounted runtime does not require another tracker restart.

## Data locations

| Path | Contents | Access |
| --- | --- | --- |
| `/var/lib/lazyarb-keitaro/{tmp,pending,processing,retry,failed}` | Durable queue | Tracker write, worker read/write |
| `/var/lib/lazyarb-keitaro/state` | Lock and heartbeat | Worker read/write |
| `/etc/lazyarb-keitaro/endpoints.d/*.url` | Postback endpoint URLs and tokens | Worker only |
| `/var/log/lazyarb-keitaro/worker.log` | JSON delivery and retry log | Worker and host administrator |

Failed events can include ad and Keitaro sub IDs. Treat queue backups as customer data and apply the same access controls as the Keitaro database.

## Local development

```sh
make verify
make image
docker run --rm --entrypoint /usr/local/bin/keitaro-worker \
  lazyarb/keitaro-worker:local version
```

Run one queue batch without starting a daemon:

```sh
LAZYARB_QUEUE_ROOT=/tmp/lazyarb/queue \
LAZYARB_ENDPOINTS_ROOT=/tmp/lazyarb/config/endpoints.d \
LAZYARB_LOG_FILE=/tmp/lazyarb/log/worker.log \
go run ./cmd/keitaro-worker once
```

## Delivery guarantees

- Atomic queue publication on the local filesystem.
- Bounded concurrent delivery with pooled HTTP connections.
- Exponential retries for network errors, HTTP 408/425/429, and 5xx responses.
- Immediate dead-lettering for permanent 4xx responses.
- Recovery of interrupted `processing` and partially published queue files.
- At-least-once delivery: a process crash after the receiver commits but before local acknowledgement can produce a duplicate request.

## Releases

Tags matching `v*` produce:

- Linux `amd64` and `arm64` static binaries with SHA-256 checksums;
- a multi-architecture image at `ghcr.io/lazyarb/keitaro-worker`;
- BuildKit SBOM and provenance attestations;
- a keyless Cosign signature;
- a GitHub release containing the immutable binary artifacts and image digest.

All workflows use LazyArb self-hosted runners. Code from external forks is not executed automatically on those runners; maintainers review it before running CI from an organization branch.
